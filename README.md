# 檢討點題

考卷檢討時，讓學生用手機匿名點選「想聽講解的題目」，老師即時看到每一題有幾個人想問，由多到少排序。

- 學生：掃 QR code，不用登入、不用密碼，點題號後按送出。
- 老師：打開 `/teacher`，輸入密碼，用講的或打字設定這次的題型和題號，看排序，檢討完按「結束這次檢討」，資料全部清掉。
- 同一時間只有一場檢討。網址和 QR code 永遠不變，每堂課重新設定題目即可。

## 檔案（全部放在最外層，沒有資料夾）

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 學生頁（QR code 指向這裡） |
| `teacher.html` | 老師頁（網址是 `/teacher`） |
| `student.js` | 學生頁程式 |
| `teacher.js` | 老師頁程式 |
| `style.css` | 共用樣式 |
| `_worker.js` | 後端：儲存題目和投票、檢查老師密碼 |
| `README.md` | 這份說明（不上傳也可以） |

檔名要一字不差，包括 `_worker.js` 開頭的底線。

## 上線步驟（只做一次，約 10–15 分鐘，手機可以做）

### 1. 把檔案放到 GitHub

1. 用手機瀏覽器開 GitHub 的 repository 頁面。
2. 按 **Add file → Upload files**。
3. 按 **choose your files**，一次選好 6 個檔案：`index.html`、`teacher.html`、`student.js`、`teacher.js`、`style.css`、`_worker.js`。
4. 等檔案列出後，按 **Commit changes**。

如果下載到手機的檔名被改成 `index (1).html` 這種，先改回原本的檔名再上傳。

### 2. 註冊 Cloudflare

到 cloudflare.com 註冊免費帳號。

### 3. 建立資料庫

1. 登入後，在左側選單找到 **D1 SQL database**。
2. 按 **Create Database**，名稱填 `review-poll`，按 **Create**。

不用建立任何資料表，網頁第一次使用時會自己建好。

### 4. 連接 GitHub 並部署

1. 左側選單進入 **Workers & Pages**。
2. 按 **Create application**，選 **Pages**，再選 **Connect to Git**。
3. 選 **GitHub**，登入授權，選你的 repository，按 **Begin setup**。
4. 設定如下：
   - Production branch：`main`（或你 repository 的主要分支）
   - Framework preset：**None**
   - Build command：`exit 0`
   - Build output directory：`/`（代表最外層）
5. 按 **Save and Deploy**，等它跑完。

完成後會得到一個網址，例如 `https://review-poll.pages.dev`。

如果部署失敗，並提示找不到輸出資料夾，到專案的 **Settings → Build** 把 Build output directory 改成留空，或改填 `.`，再到 **Deployments** 重新部署。

### 5. 設定老師密碼和資料庫

在剛剛的 Pages 專案裡，進入 **Settings**：

1. **Variables and Secrets** → **Add**
   - Variable name：`TEACHER_PASSWORD`
   - Value：你想用的老師密碼
   - 選 **Encrypt**（加密），按 **Save**
2. **Bindings** → **Add** → **D1 database bindings**
   - Variable name：`DB`（要全大寫，一字不差）
   - D1 database：選 `review-poll`
   - 按 **Save**

設定要在「Production」（正式環境）那一欄。

### 6. 重新部署

綁定和密碼要重新部署才會生效：進入專案的 **Deployments**，找到最新一筆，按右邊的 `⋯`，選 **Retry deployment**。

### 7. 試用

- 老師頁：`https://你的網址/teacher`，輸入密碼。
- 學生頁：`https://你的網址/`。

老師頁登入時如果出現「還沒設定老師密碼」或「還沒綁定資料庫」，代表第 5、6 步有漏，回去檢查變數名稱（`TEACHER_PASSWORD`、`DB`）和是否重新部署。

### 8. 做 QR code

把學生頁的網址（`https://你的網址/`）丟進任何免費的 QR code 產生器，下載圖片，交給班導師印在考卷上。網址不會變，所以只要做一次。

## 每堂課怎麼用

1. 打開老師頁（第一次輸入密碼後，這支手機會記住）。
2. 在「這次考卷」設定題目，有兩種方式，可以混著用：
   - 快速填表：在輸入框用講的或打字，先講大結構，再補小題，例如
     `單選題，1~20題。填充題，1~2題。素養題，1~5題。填充題的第1題有3個小題。填充題的第2題有2個小題。素養題的第5題有2個小題。`
     按「填入卡片」，下面會出現一張一張的題型卡片。
   - 直接用卡片：按「＋加一種題型」，用下拉選單選題型，填題號。
3. 檢查每張卡片最下面「會產生：…」那一行，題號不對就直接改卡片，確定後按「建立這次的題目」。
4. 學生掃 QR code，點想問的題號，按送出。
5. 老師畫面每 3 秒自動更新，由人數多到少排序。講完一題就點一下那一題，標記為已講解。
6. 檢討完按「結束這次檢討」，題目和所有回覆都會清掉。

### 題型卡片

每張卡片是一種題型：

- **題型**：下拉選單有單選題、多選題、選擇題、填充題、題組、混合題、素養題、閱讀題、進階題、簡答題、計算題、非選擇題，最後一個「自訂」可以自己打名稱（最多 12 個字）。
- **題號**：「從 □ 到 □」。題號不連續就按「＋加一段」，例如第一段 1 到 10、第二段 13 到 13、第三段 15 到 18。「到」留白，或和「從」填一樣，就是只有一題。素養題如果用字母，可以填 A 到 E。
- **小題**：三種做法可以一起用。
  - 「每題都有 □ 個小題」：每一題都拆成一樣多的小題。
  - 「＋指定某題有小題」：指定第幾題有幾個小題，例如第 1 題 3 個、第 2 題 2 個。
  - 兩個一起用時，指定的優先。想讓某一題沒有小題，就指定它有 0 個。
- 卡片最下面會即時顯示結果，例如 `會產生：1(1), 1(2), 1(3), 2(1), 2(2)（共 5 題）`。有 ⚠ 的地方代表某個設定沒用到（例如指定的題號不在範圍內），照提示修正。
- 同一個題型請合成一張卡片，用「＋加一段」，不要開兩張同名的。

小題的題號寫成 `1(1)`、`1(2)`、`2(1)`，學生按鈕和老師排名都是這樣。題組要接著大題號（例如 21、22、23），就當成一般題號填一段；要自己從 1(1) 開始編，就用小題設定，兩種做法用的是同一套。

### 快速填表的說法

建議固定用這兩種句型，最不容易出錯（輸入框上方也一直顯示著提示）：

- 大結構：`題型名稱，x~x題`，例如 `單選題，1~20題`、`素養題，1~5題`。
- 小題：`題型名稱的第x題有x個小題`，例如 `填充題的第1題有3個小題`。

按「帶入範例」會把一整段範例放進輸入框，改成自己的數字就能用。念或打好之後按「填入卡片」，辨識結果會變成卡片，再用下拉選單和數字修正。如果卡片已經手動改過，再按「填入卡片」要按兩次，避免不小心蓋掉。

說明：

- 有小題的那一題，會被它的小題取代。填充題第 1 題有 3 個小題、第 2 題有 2 個小題，會變成 1(1)、1(2)、1(3)、2(1)、2(2)。
- 小題句放在大結構前面或後面都可以，同一個題型的小題句可以接著念，不用每句都重複題型名稱。
- 只念總題數也可以：`單選題，20題` 會變成 1 到 20 題。
- 舊的說法仍然可用：跳著念 `選擇 1 到 10，13，15 到 18`、排除 `選擇 1 到 20 不含 11 12`、素養用字母 `素養 A 到 E`。
- 支援的題型名稱：選擇、單選、多選、填充、進階、素養、題組、混合、閱讀、簡答、計算、非選擇等。不在下拉選單裡的名稱，卡片會放成「自訂」，名稱不是常用題型時會標示「⚠ 這個名稱不是常用題型，請確認」。

### 麥克風按鈕「念一句」

輸入框下面如果有「念一句」按鈕，就可以直接在網頁裡語音輸入，不必用鍵盤上的麥克風：

- 按一下開始，念一句（例如 `單選題，1~20題`），停頓一下會自動停，辨識的字會接在輸入框後面。要念下一句就再按一次。念完按「填入卡片」。
- 第一次按，瀏覽器會問要不要允許麥克風，選允許。如果不小心按了不允許，到瀏覽器的「網站設定」把麥克風改成允許。
- 這是瀏覽器內建的語音辨識，在 Android 的 Chrome 可以用，辨識需要連網路。看不到按鈕，代表這個瀏覽器不支援，改用鍵盤上的麥克風就好，其他功能不受影響。
- iPhone 的 Safari 雖然有按鈕，但語音辨識比較不穩（可能很快自己停、結果延遲），建議改用鍵盤上的麥克風。
- 在 LINE 等 App 裡面點開的內建瀏覽器，可能不能用，請改用手機本身的瀏覽器開老師頁。

### 語音輸入被聽錯時

手機鍵盤的語音輸入、或「念一句」，都可能打錯字或把標點放錯位置。程式已經自動處理這些情況：

- 中文數字（一到二十）和全形數字。
- 「題」被打成「提、體、梯」，「小題」被打成「小提、小體」。
- 逗號、句號放在奇怪的位置，或完全沒有標點。
- 「底下、裡面、共有」、「個、各」、「至、~、到」這些說法。
- 題型名稱聽錯，例如「題主題」會換回「題組」。對照表在 `teacher.js` 裡，搜尋 `MISHEAR` 就能找到。

沒聽懂的地方不會默默略過，按「填入卡片」後會在輸入框下面用 ⚠ 列出來：

- 提到「小題」但沒聽懂的句子，整句略過，避免亂加題號。
- 小題句指到不存在的題，或前面沒有題型名稱。
- 名稱不在常用題型內，卡片會放成「自訂」並標示「請確認」。

按「填入卡片」之前，也可以直接在輸入框裡改字。填入之後，任何地方不對都直接改卡片就好。如果發現新的聽錯寫法，請把「你念的」和「手機打出來的字」告訴我，我補進去。

## 費用和限制

- Cloudflare 的免費方案，一般補習班的使用量夠用（官方每日額度：Workers 請求 10 萬次、D1 每日寫入 10 萬列）。
- 一場檢討最多收 300 份回覆，一份考卷最多 300 題、6 種題型。每種題型最多 100 個題號（含小題），每題最多 30 個小題，題號最長 8 個字（`100(30)` 剛好）。
- 麥克風按鈕用的是瀏覽器內建的語音辨識（Android 的 Chrome 會把聲音送到 Google 辨識），只用在老師輸入題型，不涉及學生。
- 學生手機每 30 秒向伺服器確認一次老師有沒有換題，老師畫面每 3 秒更新一次。

## 注意

- 老師密碼只能擋住好奇的學生，不是銀行等級的防護。
- 學生的回覆是匿名的：資料庫只存「一組隨機代號」和選了哪些題，不存姓名或其他個人資料。隨機代號只用來讓同一支手機重送時覆蓋舊的，不會重複計算。
- 同一支手機換瀏覽器或清除網站資料後，會被當成新的一位，可以再投一次。
- 老師頁網址是 `/teacher`，後面不要加斜線。
